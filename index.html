在本地启动只读预览

克隆仓库后，在仓库根目录启动静态 HTTP 服务。该命令只读取项目文件，不会安装依赖、修改论文数据或产生 Git commit。

你在终端执行启动与停止
# 替换为你在本机克隆知域仓库的实际路径
cd /path/to/zhiyu

# 看到提示才说明目录正确
test -f index.html && test -d scripts && echo "已进入知域仓库根目录"
python3 -m http.server 8080

# 浏览器打开 http://localhost:8080/
# 预览结束后在终端按 Ctrl+C 停止服务

不要双击 index.html。 地址栏以 file:// 开头时，浏览器会阻止页面读取 JSON 和 Markdown；正确地址应以 http://localhost:8080/ 开头。

同步仓库并创建工作分支

每次更新从独立分支开始。这样 AI 产生的修改与主分支隔离，也方便团队通过 Pull Request 审阅。

Terminal · Step 1同步并建分支
# 每次打开新终端，都先进入知域仓库根目录
cd /path/to/zhiyu
test -f index.html && test -d scripts && echo "已进入知域仓库根目录"

# 若团队默认分支是 master，请把下面的 main 改为 master
git switch main
git pull --ff-only
# 将 [topic] 和 [date] 替换为实际内容，例如 papers/hoi-2026-08-20
# -c 表示新建分支。若提示 already exists：
#   尚未合入 main 时，去掉 -c 继续用同一条分支：git switch papers/[topic]-[date]
#   已经合入过（或远程仍留着旧分支）时，换一个新名字再创建，例如 papers/hoi-2026-08-20-2
git switch -c papers/[topic]-[date]

完成后继续第 2 步，在下面选择一种 AI 任务。

Important

网页操作不等于修改资源

页面中的搜索、排序、标签筛选和视图切换只改变当前页面如何展示资源，不会改写论文、报告或仓库文件。刷新或切换筛选条件后，原始资源仍保持不变。

操作实际发生的事情是否修改仓库
搜索、排序、标签筛选临时改变当前页面上的结果集合与顺序否
隐藏论文将论文 ID 保存到当前浏览器的本地存储否
保存评论将评论保存到当前浏览器的本地存储否
导出本地修改下载一份 JSON 文件，供维护者审阅和提交否
打开论文、代码或项目链接访问第三方网站提供的公开资源否
Browser state

本地状态与隐私

隐藏状态和评论保存在浏览器的 localStorage 中，只对当前浏览器配置可见，不会上传到 GitHub，也不会在设备之间同步。清除站点数据、使用隐私模式或更换浏览器后，这些状态可能消失。

如果希望把修改永久纳入文献库，需要在“数据维护”中导出修改，由仓库维护者把内容合并到 data/paper_overrides.json 并提交到 Git。

Evidence

内容与外部资源

本站展示的是研究资料的整理结果，不替代论文原文。论文元数据、摘要、阅读判断和专题报告可能存在遗漏或过时信息，关键结论应回到原论文和官方项目页核验。

外部论文、代码、模型和项目链接由各自网站维护，其可用性、许可协议、隐私政策与内容准确性不受本站控制。

方式一至三用于能够联网并访问本地仓库的 AI 编程助手：替换方括号中的内容后发送，AI 会修改当前分支并运行校验。方式四用于固定周期运行的在线 Agent：它只生成 Markdown 周报，不访问本地仓库。

  data/papers.json data/reports.json

# 最后在 GitHub 创建 Pull Request

如果 AI 新增了可靠配图，也要审阅并暂存对应的 content/images/...。不要使用 git add .，避免把其他人的本地修改或无关文件一起提交。
