# 替换为你在本机克隆知域仓库的实际路径

# 预览结束后在终端按 Ctrl+C 停止服务

Important

网页操作不等于修改资源

页面中的搜索、排序、标签筛选和视图切换只改变当前页面如何展示资源，不会改写论文、报告或仓库文件。刷新或切换筛选条件后，原始资源仍保持不变。

操作实际发生的事情是否修改仓库
搜索、排序、标签筛选临时改变当前页面上的结果集合与顺序否
隐藏论文将论文 ID 保存到当前浏览器的本地存储否
保存评论将评论保存到当前浏览器的本地存储否
导出本地修改下载一份 JSON 文件，供维护者审阅和提交否
打开论文、代码或项目链接访问第三方网站提供的公开资源否
Browser state

本地状态与隐私

隐藏状态和评论保存在浏览器的 localStorage 中，只对当前浏览器配置可见，不会上传到 GitHub，也不会在设备之间同步。清除站点数据、使用隐私模式或更换浏览器后，这些状态可能消失。

如果希望把修改永久纳入文献库，需要在“数据维护”中导出修改，由仓库维护者把内容合并到 data/paper_overrides.json 并提交到 Git。

Evidence

内容与外部资源

本站展示的是研究资料的整理结果，不替代论文原文。论文元数据、摘要、阅读判断和专题报告可能存在遗漏或过时信息，关键结论应回到原论文和官方项目页核验。

外部论文、代码、模型和项目链接由各自网站维护，其可用性、许可协议、隐私政策与内容准确性不受本站控制。

复制给 AI，不在终端运行

选择任务并让 AI 修改项目

选择一种任务，替换方括号中的内容，然后把整段提示词发给能够联网并访问本地仓库的 AI 编程助手。AI 会直接修改当前分支中的文件并运行校验。

三套提示词都要求 AI 停在未提交状态：不得执行 git commit、git push 或创建 Pull Request。

方式一

让 AI 直接检索论文

你正在维护当前独立的“知域”研究知识库。请围绕“[研究主题]”检索并新增论文，检索范围为“[时间范围，例如过去三个月]”，预计收录 [数量] 篇。请完整执行，不要只给建议。

如果用户还没有提供研究主题、时间范围或期望数量，请先逐项询问用户；得到明确回答后再开始检索，不要自行猜测。

开始前：
1. 先确认当前工作目录是知域仓库根目录，其中必须包含 index.html、data、content 和 scripts；如果不是，请停止并让用户提供正确的仓库路径。然后阅读 README.md 和 CONTRIBUTING.md，遵守其中的证据、格式和维护要求。
2. 检查 git status 和现有 content/reports、data/papers.json，保留工作区中不是你产生的修改，不得覆盖或回退他人内容。
3. 先按 arXiv ID、DOI 和规范化标题检查重复；同一工作的预印本、会议版和期刊版应合并判断，避免重复收录。

检索与核验：
1. 可以从 arXiv、Google Scholar、Hugging Face Papers Daily、papers.cool 等获取线索，但必须优先核对原论文、正式出版页、官方项目页和官方代码仓库。
2. 尽可能阅读论文正文，不能只根据标题或摘要编造。若只能访问摘要或二手资料，明确标记信息范围和置信度。
3. 每篇论文记录标题、作者、年份与发表状态、arXiv/DOI、论文/项目/代码/数据/模型/AlphaXiv 链接、类别标签、核心 Insight、Pipeline 的输入/过程/输出、实验与证据、代码数据开放情况、局限与失败案例。
4. 严格区分作者主张、实验实际支持的结论和你的分析。核对数据集、指标、baseline、公平性、消融、统计波动、计算成本和数据泄漏风险。
5. 配图只有在来源和图号可核验时才加入，并记录论文名、图号和来源链接；不要为凑数添加图片。

写入与校验：
1. 在仓库根目录新建 content/reports/[YYYY-MM-DD_topic_slug].md。在开头写“**报告标签**：[标签1, 标签2]”；使用一个一级标题；每篇论文使用“## 1. 论文标题”形式的连续编号二级标题，并设置“作者”“年份与发表”“核心内容与 Insight”“Pipeline”“实验与证据”“代码与数据”“局限、失败案例与开放问题”等清晰小节。
2. 在仓库根目录运行：
   python3 scripts/ingest_reports.py
   python3 scripts/enrich_arxiv.py
   python3 scripts/validate_data.py
   python3 scripts/check_asset_budget.py
3. 检查生成的数据和 git diff，确认没有重复记录、无效链接、意外删除或无关改动。若 arXiv 网络补全暂时失败，说明情况，但仍完成其余校验。
4. 不要执行 git add、git commit 或 git push；保留修改供用户审阅。

最后报告：检索日期、检索范围、纳入/排除数量、关键新增论文、修改文件、校验结果、建议的 commit message，以及仍需人工核验的问题。

如果用户还没有在提示词末尾提供论文列表，请先让用户粘贴论文标题、arXiv 链接、DOI 或项目页；收到至少一条可识别线索后再开始，不要自行猜测列表。

先确认当前工作目录是知域仓库根目录，其中必须包含 index.html、data、content 和 scripts；如果不是，请停止并让用户提供正确的仓库路径。然后阅读 README.md 和 CONTRIBUTING.md。检查 git status，保留所有不属于你的现有修改。检查 data/papers.json，并按 arXiv ID、DOI、规范化标题识别重复和同一论文的不同版本；已有记录应补充或关联来源，不要创建重复条目。

对列表中的每篇论文：
1. 优先访问原论文、正式出版页、官方项目页和官方代码仓库，核对准确标题、完整作者、年份、发表状态、arXiv ID、DOI 及可靠链接。
2. 尽可能阅读正文，整理类别标签、核心 Insight、Pipeline 输入/过程/输出、实验设置与结果、证据真正支持的结论、代码与数据开放情况、局限和失败案例。
3. 明确区分作者声称、实验事实和阅读者推断；无法全文核验的字段要标注“仅据摘要/待核验”，不得猜测。
4. 只在图片来源、论文名称和图号都可核验时加入代表图。

将结果写入仓库根目录的 content/reports/[YYYY-MM-DD_curated_papers].md：在开头写“**报告标签**：[标签1, 标签2]”；使用一个一级标题，每篇论文使用“## 1. 论文标题”形式的连续编号二级标题，并包含“作者”“年份与发表”“核心内容与 Insight”“Pipeline”“实验与证据”“代码与数据”“局限、失败案例与开放问题”等小节。

然后在仓库根目录运行：

检查 git diff，确保没有意外删除、重复记录或无关改动。不要执行 git add、git commit 或 git push；保留修改供用户审阅。最后给出已收录、合并到已有记录、排除、待核验的论文清单，校验结果和建议的 commit message。

方式三

专题检索与综述报告

你正在维护当前独立的“知域”研究知识库。请针对“[专题或研究问题]”完成一次可核验的专题检索与研究脉络梳理，同时把论文元信息和完整专题报告持久化到仓库。时间范围为“[时间范围]”，重点回答“[希望回答的核心问题]”。

如果用户还没有提供专题、时间范围或希望回答的核心问题，请先逐项询问用户；得到明确回答后再开始研究，不要自行设定范围。

先确认当前工作目录是知域仓库根目录，其中必须包含 index.html、data、content 和 scripts；如果不是，请停止并让用户提供正确的仓库路径。然后阅读 README.md 和 CONTRIBUTING.md；检查 git status、既有专题报告和 data/papers.json，保留他人修改并做好去重。

研究要求：
1. 制定检索词、纳入标准和排除标准，记录检索日期。线索来源可以广泛，但关键事实必须回到论文原文、正式出版页和官方项目核验。
2. 选择能够覆盖奠基工作、关键技术分支、代表性方法、最新进展和反例/负结果的论文，不要只罗列近期论文。
3. 对每篇论文记录完整元信息、可靠链接、标签、Insight、Pipeline、实验与证据、开放情况、局限。明确全文已读、仅摘要可见或二手线索的证据等级。
4. 报告应进一步比较问题定义、输入输出、表示方式、训练信号、数据集、指标、计算成本和适用边界；总结一致结论、争议、证据缺口、发展趋势，以及可能影响选题 novelty 的工作。
5. 不得把相关性写成因果性，不得把作者主张写成已被实验充分证明的事实。

将报告写入仓库根目录的 content/reports/[YYYY-MM-DD_topic_survey].md。在开头写“**报告标签**：[标签1, 标签2]”；使用一个一级标题；先写分类比较、研究脉络、证据审计、开放问题和选题建议，再写论文条目。单篇论文条目统一使用“## 1. 论文标题”形式的连续编号二级标题并放在报告末尾，确保导入器能够准确识别边界。

然后在仓库根目录运行：
python3 scripts/ingest_reports.py
python3 scripts/enrich_arxiv.py
python3 scripts/validate_data.py
python3 scripts/check_asset_budget.py

检查网站数据与 git diff，确保去重正确、报告可在“专题报告”中打开、没有意外删除或无关改动。不要执行 git add、git commit 或 git push；保留修改供用户审阅。最后报告检索策略、纳入与排除情况、主要结论、变更文件、校验结果、建议的 commit message 和待人工复核项。
