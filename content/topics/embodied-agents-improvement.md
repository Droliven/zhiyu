# 具身 Agent 的执行范式与自我改进

**更新日期**：2026-11-11

**报告标签**：Agent与可执行世界, 机器人学习, World Action Model, 具身上下文学习, 数据与评测

机器人系统里的代码、几何和未来预测，可能承担完全不同的职责。代码可以是动作模型读取的中间变量，也可以直接调用控制器；几何可以帮助估计当前场景，也可以描述候选动作的未来后果。只看是否使用 Agent、4D 或 WAM，无法判断系统究竟怎样决策。

理解这些工作的起点，应是沿着部署时的执行路径追问：**谁产生要执行的动作，什么证据决定接受这个动作，执行反馈又写回哪里？** 前两问区分控制与世界模型的计算机制，第三问区分当前适应与持久改进。它们提供可核对的分界，不要求把整篇论文硬塞进一个互斥类别。

## 第一条分界是模型生成动作还是生成控制程序

这里讨论的是任务相关的动作段，不是底层伺服控制器。在 AW-0 默认模式中，代码、视频与动作共同生成，机器人执行动作专家输出的动作块；代码在推理中影响动作，却不被执行器运行。在 AMP1 中，通用模型生成的 Python 会实际调用几何计算、轨迹规划和控制接口，机器人执行由程序落实的动作。两者都使用预训练模型，也都根据新观测重新决策；真正的区别是**代码位于动作生成网络内部，还是具有外部执行权**。[AW-0 §2.3](https://arxiv.org/html/2610.30136v1#S2.SS3)、[AMP1 §4](https://arxiv.org/html/2611.09892v1#S4)。

这个区别直接决定可修改的对象。AMP1 可以改坐标计算、调用顺序和下一段控制程序，但结果仍受工具与执行器能力约束。AW-0 可以生成不同程序条件和动作，却不能仅靠解释程序文本，就确认动作专家遵守了其中每一条语句。它的代码既不只是离线训练标签，也不自动等同于有独立执行语义的策略。

LAW 则把两种责任分开：高层模型管理子任务，WAM 产生动作候选，学习式 value 对候选评分并融合。它不是第三种与“训练内化”“在线推理”互斥的路线，而是一个明确的控制分层。GroundingPI 本身是感知模型；连接 Action DiT 后，动作仍由训练策略产生。SpatialHarness 则增强冻结模型可读取的场景信息，主要改变观测接口。[LAW §3.1](https://arxiv.org/html/2610.23334v2#S3)、[GroundingPI §4](https://arxiv.org/html/2609.39601v2#S4)、[SpatialHarness §3](https://arxiv.org/html/2610.12457v1#S3)。

| 工作与配置 | 部署时的主要动作路径 | 决策可改动的对象 |
| --- | --- | --- |
| AMP1 | 观测→通用模型→可执行程序与工具→轨迹 | 测量方法、程序和动作参数 |
| LAW | 子任务→WAM动作候选→value评分融合→动作块 | 子任务、候选选择与动作块 |
| AW-0 默认 | 观测→代码／视频／动作联合生成→动作专家输出 | 联合生成中的程序条件与动作 |
| GroundingPI 机器人适配 | 观测→感知骨干特征→Action DiT→动作块 | 感知与动作网络的输出 |
| SpatialHarness | 观测→同步场景与辅助视图→冻结模型→动作 | 当前场景和策略所见的空间信息 |

这是对实际配置的描述。AW-0 的混合模式允许通过检查的代码接管阶段，会改变其执行路径；不能用默认模式的结论概括全部设置。

## 第二条分界是世界信息怎样参与动作选择

“具有世界模型”至少需要拆开三种计算机制：**未来预测用于训练、预测变量参与动作生成、给定候选动作后预测其后果以供优化。** 这三种方式可以组合，但并不等价。特别是，接受过视频预测训练，不等于部署时会在预测的世界里比较行动方案。

LAW 是一个清楚的例子。其视频分支提供联合训练信号，部署时不生成未来视频；候选动作由 value expert 直接评分。这个评分可以包含学到的后果知识，但执行路径不是“对每个候选模拟未来场景，再按场景结果选动作”。因此，LAW 的关键贡献应从进度协调、动作选择与信用分配理解，而不能从 WAM 名称推导出显式想象规划。[LAW §3.1、算法1](https://arxiv.org/html/2610.23334v2#S3)。

AW-0 和 Gnomon4D 则保留了生成过程中的预测变量。尤其 Gnomon4D 让动作专家在联合去噪中读取机器人与物体的相对运动，按交互区域和转换时刻聚合几何未来。这是真正的推理期预测利用，不能因为没有外部搜索就说它“不使用世界模型”。但联合生成一组相互协调的未来与动作，仍不同于固定一个外部候选动作、查询后果、再据此修改候选。[AW-0 §2](https://arxiv.org/html/2610.30136v1#S2)、[Gnomon4D §3.4–3.6](https://arxiv.org/html/2611.02474v2#S3)。

PointWorld 提供后一种接口：候选机器人轨迹作为输入，模型预测场景点的运动，外部优化器按目标距离等成本更新轨迹。动作的产生与后果的预测可以分别调用，预测也因而可以接受“换一个动作会怎样”的检验。代价是多轮候选预测和显式目标成本。其v1真机实验需要数秒规划，并未执行中重规划；约0.1秒的模型forward不能当作整个闭环周期。[PointWorld §3.2、附录A.6](https://arxiv.org/html/2601.03782v1)。

| 世界信息的用途 | 它在部署中做什么 | 代表 |
| --- | --- | --- |
| 训练得到的预测知识 | 改善策略表征；不输出场景未来供决策使用 | LAW 所用 Fast-WAM 路径 |
| 联合生成中的预测变量 | 与动作共同推断，动作读取未来信息 | AW-0、Gnomon4D |
| 可单独调用的前向动力学 | 接受指定动作，预测后果，供成本评估与动作优化 | PointWorld |

这也解释了为什么不能把 GroundingPI 与 SpatialHarness 直接归为第三行。前者主要改善“当前图像中在哪里”，后者主要维护“当前场景是什么状态”；SpatialHarness 的候选重放服务于状态校正，并不自动成为候选行动的未来规划。**估计现在与预测行动后果是两个问题。** 更准确的状态可以帮助规划，但不是规划算法本身。

## 第三条分界是反馈改变当前执行还是改变后续求解

一个系统观察到抓取失败并重试，改变的是当前行动；它修正物体位姿，改变的是当前状态估计。只有新获得的程序、经验或参数被保留并帮助后续任务，才能进一步讨论跨回合改进。是否修改神经网络权重不是唯一标准，代码与外部知识同样可以承载学到的能力。

AMP1 基础配置主要在当前任务中修订代码与策略，AMP1+增加跨回合记忆。ASPIRE 将执行证据转化为经验证的修复知识，EmbodiedEvo 则把探索结果保存为 Skills/Lessons，再交给新的执行者。它们不应与“神经策略还是程序控制”并列成另一种执行范式；这是同一个执行系统能否积累经验的问题。[AMP1 §2C](https://arxiv.org/html/2611.09892v1#S2.SS3)、[ASPIRE §2](https://arxiv.org/html/2607.00272v2#S2)、[EmbodiedEvo §3.4](https://arxiv.org/html/2610.18867v2#S3)。

是否在部署中继续调用 Agent，也必须看具体实验。ASPIRE 在 LIBERO/Robosuite 中复用已生成程序评测，在 BEHAVIOR-1K 中却根据当前执行记录增量生成代码块。因此，“先搜索程序”与“在线 Agent”可以存在于同一工作，不能仅凭论文名断定 LLM 已经出环。[ASPIRE §3.3](https://arxiv.org/html/2607.00272v2#S3.SS3)。

RSI 要求更进一步区分**被改进的能力**与**产生改进的方法**。新技能让执行变好，是能力改善；过去修复经验让下一次实验选择或程序修订更有效，才涉及改进过程；更强的递归主张还要检验改进者如何生成更好的自身后继。反复运行固定搜索、扩大技能库和提高任务成功率，都不能单独回答最后一个问题。[Physical RSI §2.2](https://arxiv.org/html/2610.29677v1#S2)。

## 这些分界怎样约束研究选题

现在可以把“agentic 4D WAM”拆成三个不同的技术选择。把4D放在观测侧，是研究更好的状态估计或空间接口，直接近邻是 SpatialHarness 与 Geometric Abstraction；把4D放进联合生成，是研究动作如何使用几何预测，Gnomon4D 已经提供具体机制；把4D做成可查询的动作条件模型，则进入基于预测的行动优化，PointWorld 是明确参照。三条路线解决的问题、训练数据和计算成本都不同，不能先用一个名称把它们合并。

对 WAM 与 Agent 的结合，值得先做的比较是：**同样的观测和候选动作，显式预测后果究竟比直接 value 评分多解决了什么？** LAW 展示了直接评分的路径，PointWorld 展示了预测再优化的路径，联合生成又提供第三种利用未来的方式。它们现有结果并未在统一条件下分出优劣。比较还需匹配目标、训练数据、监督权限与计算预算；若一方额外获得深度、轨迹或奖励标签，收益便不能单独归于预测机制。这个比较能判断世界模型应该承担什么职责，比泛泛要求“更多空间理解”更具体。

一个有解释力的探查可以固定候选集合，改变接触对象、运动方向或操作时序，分别检查预测是否响应动作变化、预测是否准确、以及由预测得到的选择是否改善真实执行。三项需要分别成立：预测出合理画面，不代表对候选动作敏感；对动作敏感，不代表后果正确；后果更准确，也不代表在同等预算下比value更会选动作。4D的贡献应落实到这些区别中，例如它是否改善了决定选择的相对运动或接触结果，而不是仅降低平均重建误差。

这是一条可执行的研究入口，尚不是现成创新点。基于模型规划、几何约束、技能前提学习和程序复用均已有长期研究。只有先观察到明确失效，才能决定贡献应落在动作条件化、预测与执行的一致性、目标评估，还是规划计算本身。当前比较还不能推出“技能适用性是主要瓶颈”，也不能保证显式4D优于同信息量的历史latent模型。

效率和可靠性同样应沿计算机制衡量。AMP1在推理时暂停的仿真结果不能证明及时响应；SPARK能否自主触发恢复受成功判定信号影响；EmbodiedEvo复用结构经验比重放历史便宜，并不等于含经验获取的总成本更低。这些协议决定的是方法能支持什么结论，而不是给某条路线贴上“快”或“稳”的标签。[AMP1 §4](https://arxiv.org/html/2611.09892v1#S4)、[SPARK 附录K](https://arxiv.org/html/2606.30613v5)、[EmbodiedEvo 附录E](https://arxiv.org/html/2610.18867v2)。
