## 当前挑战

动作策略会在陌生物体、指令和失败情形中失效；高层 Agent 调用固定技能也可能看不到失败细节。本文检验通用模型直接编写、执行并检查动作代码，能否减少这些限制。

## 研究动机

**让通用模型持续参与控制，把感知、几何计算与动作执行暴露为可检查的接口。** 核心贡献是机器人 harness 和系统性实证；没有提出新的空间表征学习或追踪算法。

## 技术方案

**输入**：任务、机器人状态，以及按需读取的图像、深度、标定和场景对象；具体权限随基准变化。

**过程**：冻结模型在持久 Python 内核中测量几何、编写动作代码并检查结果。SDK 提供对象跟踪、渲染、轨迹检查和执行；基本接口不替模型选择抓取或放置策略。AMP1+另将代码和经验保存在跨 episode 记忆中。

**输出**：带时间的末端位姿轨迹和夹爪指令；反馈可改变当回合策略，部署不更新模型权重。[方法 §4](https://arxiv.org/html/2611.09892v1#S4)。

## 实验结果

RoboLab-120 零样本成功率最高为85.6%；真机十二任务、三台机器人共104/108次成功。更有区分力的是同 Opus 5.5 的消融：完整几何工具82.8%，去工具81.9%，平均模型调用34.8→38.7。工具对强模型主要体现效率价值，主成功率不能归于新的定位机制。[分析 §2D、Fig.5](https://arxiv.org/html/2611.09892v1#S2.SS4)。

AMP1+在 RoboDojo 从26.4%升至84.1%，但每任务最多48次练习，五次练习运行择优后冻结记忆评测。RoboLab、CaP-Gym 和 RoboDojo 在模型推理时暂停仿真；前两者提供无噪深度和精确标定。作者按论文时 API 价格计算 Opus 5.5 平均每 episode **1.39美元**，不含全部系统成本。[§2C、§4C–G、补充S7](https://arxiv.org/html/2611.09892v1)。

## 总结讨论

本文支持强通用模型通过适当接口完成复杂闭环操作。跨回合记忆改善了任务表现，但尚未证明改进机制本身递归增强；场景跟踪也不足以使其成为精细4D定位方法的代表。

## 局限、失败案例与开放问题

- 模型执行轨迹时不能重新考虑，准静态结果不能外推到快速滑落或移动目标。
- 与 Astranomy 的同模型比较同时改变代码执行、动作粒度和场景模型，未隔离各项贡献。
- 暂停仿真使成功率与真实等待成本分离，部署比较需同时报告调用、token和端到端时间。
