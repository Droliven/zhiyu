## 当前挑战

将 2018 年就已提出的 Loop Transformer 真正推上 **750B 参数、1M 上下文**的旗舰生产级大模型，学术界与工业界此前一直卡在三道硬门槛上：

- **“从头训循环”在等算力下打不过非共享模型**：预训练早期模型需要大量独立参数来吞吐与记忆海量世界知识；若从零强制权重共享，同等训练算力下知识容量吃亏，最终表现反而不如常规 Transformer。
- **强行把预训练大模型改造成循环会直接炸分布**：把中段层的输出直接回灌给前面已训练好的层，会导致激活范数跨轮次爆炸，下游层收到完全分布外（OOD）的特征向量，轻则精度崩盘、重则训练发散。
- **长上下文 KV 缓存按循环轮数线性暴涨**：如果 1M 上下文下每轮循环都独立存一份完整 KV 缓存并重新跑稀疏注意力检索，推理显存与访存带宽立刻翻倍，生产部署完全不可接受。

## 研究动机

**核心 Insight：把“知识记忆”和“深度推理”按训练阶段与结构解耦——先用非共享预训练（GLM-5）吃满大规模参数记忆，再通过低成本继续训练把中段 28 层改造成“带逐 Token 门控与混合 KV 缓存的双轮 Loop Transformer”，将一部分冗长的显式 CoT 思考内化为隐式计算深度。**

这条路线极具工业界务实智慧：

- **只用 ~10% 额外训练算力撬动深度红利**：跳过从头训循环的沉没成本，在成熟底座上直接叠加循环深度，瞄准 Z.ai 定义的“泛化编程（Generalized Coding）”——即以代码级严密因果逻辑驱动大型软件工程、网络安全、3D 建模与游戏构建等超长链任务。
- **用门控自发涌现“隐式难度路由”**：看似固定执行 2 轮循环，实则靠逐 Token 独立门控让简单 Token 与困难 Token 在第一轮就分化出截然不同的写入幅度，在不破坏 GPU 批处理的前提下逼近自适应计算的效果。

## 技术方案

**输入**：最长 **1M Token** 上下文的多模态输入（文本、文件、图像与原生视频），支持最高 **128K Token** 输出。

**过程**：输入经开端层编码后，进入由 GLM-5 底座改造的中段 **28 层权重共享模块**并执行 **2 轮迭代**；每轮由独立逐 Token 门控按比例将候选更新写回残差流，第二轮复用第一轮的全局稀疏 KV 缓存与稀疏注意力索引、仅维护 128 Token 局部滑窗；最后经末端层输出。

**输出**：显式思维链更凝练、长链逻辑推理更强的代码、规划与 Agent 执行输出。

三大关键工程机制拆解（为什么能稳在 750B × 1M 上下文）：

- **机制一：逐 Token 渐进门控（Per-Token Gated Progressive Updates）及其涌现分工**
  - 为每轮循环引入独立的逐 Token 门控，按比例把循环块的候选更新写入主残差流，从根本上压住激活范数爆炸并平滑过渡到原预训练下游层的分布。
  - **极具启发性的涌现现象**：训练后两轮门控自发形成明确分工——**第一轮（Pass 1）保持保守（门控值偏小）**，主要负责聚合全局上下文并稳住特征尺度；**第二轮（Pass 2）打开门控**，写入完整精炼后的逻辑更新。同时，面对**高难度推理 Token**，第一轮门控会动态放大写入幅度，让困难 Token 在进入第二轮前就携带更丰富的中间推理态。
- **机制二：重叠式混合 KV 缓存（Hybrid KV Cache）**
  - 第二轮循环**直接复用第一轮选出的全局长程稀疏 KV 缓存**，同时仅为最近约 **128 Token** 维护第二轮专属的局部滑动窗口 KV。
  - 精妙之处在于两者在最近 128 Token 位置上是**重叠共存**的：第二轮注意力既能低成本回望 1M 长度的全局一轮上下文，又能敏锐捕捉刚刚经过二轮精炼的局部最新语义，而无需为 1M 上下文多付一倍 KV 显存。
- **机制三：稀疏注意力索引复用（Sparse Attention Index Reuse）**
  - 第二轮直接沿用第一轮已算好的稀疏注意力索引选择，省去昂贵的二次长程检索开销，把循环新增成本严控在纯前向计算以内。

## 实验结果

官方首发尚未放出 750B 旗舰版完整外部 Model Card 榜单，但公布了一组干净的 **30B 等参数对照消融**（仅增 ~10% 训练算力，均开启 Thinking 模式）：

| 评测基准 | 30B 基线（非循环） | 30B + Loop 架构 | 绝对提升 | 平均输出长度变化 |
| --- | ---: | ---: | ---: | ---: |
| **AIME25**（竞赛数学） | 19.17 | **30.42** | **+11.25** | −2.0% |
| **GPQA-Diamond**（专家科学） | 47.58 | **56.26** | **+8.68** | −11.7% |
| **AA-LCR**（长上下文推理） | 40.33 | **47.67** | **+7.34** | −9.7% |
| **MMLU-Pro**（综合知识推理） | 71.65 | **75.05** | **+3.40** | −14.9% |
| **IFBench**（指令遵循） | 50.20 | **53.47** | **+3.27** | −13.0% |

**数据背后的核心规律**：
1. **越偏多步硬推理，循环增益越大**：数学竞赛（AIME25 +11.25）与博士级科学推理（GPQA +8.68）收益远大于偏知识检索的 MMLU-Pro（+3.40），直接印证“物理参数管记忆、循环深度管推理”的分工假说。
2. **“精度涨、废话少”的思考内化效应**：5 项基准输出长度全部缩短（−2.0% 至 −14.9%），说明模型把一部分原本必须吐成文本草稿的中间步骤，消化进了 28 层 × 2 轮的隐式潜空间深度里。

## 总结讨论

### 核心 Takeaway 与可迁移启示

1. **给所有想把现有大模型/VLA 改造成 Loop 的团队：抄这套“继续训练 + 逐 Token 门控”配方**。不要推倒重训！在成熟预训练底座的中段截取一个连续块做 2 轮循环，用逐 Token 门控从近似恒等映射平滑切入，只需约 10% 额外训练算力就能换来大幅深度收益，这套范式同样可直接迁移到多模态 VLA 或机器人策略主干的“后训练深度增强”。
2. **“固定轮数 + 逐 Token 门控”是当下 GPU 友好的准自适应计算**：相比难以 batch 并行的硬早停（ACT），逐 Token 门控在不牺牲张量规整性的前提下，让模型自发按 Token 难度调节第一轮写入强度，是极高性价比的工程折中。
3. **隐式深度可以缩短显式 CoT，但也会引入新的失控模式**：一方面，更短的显式输出部分抵消了每 Token 两轮循环的计算开销；另一方面，实测反馈 GLM-5.4 在极端难题下会陷入“马拉松思考（marathon thinking）”，说明隐式循环深度 + 显式长思维链叠加后，若缺乏停止校准，整体端到端延迟反而可能急剧膨胀。

### 批判性审视与证据边界

必须严格区分**已证实的 30B 消融**与**待核验的 750B 主张**：30B 等参实验扎实证明了该循环改造机制的有效性，但“750B 循环版达到 2T–3T 参数级智能”目前仍属官方定位口径，且 750B 的精确 MoE 激活参数、真实吞吐（tokens/s）与外部盲测榜单尚未公开。

## 局限、失败案例与开放问题

- **750B 实证透明度不足**：缺少 750B 完整外部基准对照、精确激活参数及同算力下与非循环大模型的真实推理延迟/成本对比。
- **“马拉松思考”延迟风险**：隐式深度提升并不自动消除过度自我纠错，在最大努力推理模式下偶发冗长思考循环，拉高响应时延与 Token 账单。
- **仍停留在固定 2 轮循环**：尚未验证在 750B 规模下扩展到 3–4 轮是否继续单调增益，也未实现真正节省 FLOPs 的简单 Token 硬早停。
- **长上下文二轮滑窗截断边界**：混合 KV 缓存仅在 128 Token 局部窗口维护二轮新特征，若复杂任务需要对几千 Token 外的远距信息做二轮精细重写，该近似是否存在精度上限尚无公开消融。
