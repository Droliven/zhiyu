## 当前挑战

海量机器人操作视频没有同步的动作标注，而用现有 4D 点跟踪器直接从 RGB 恢复机器人动作会撞上两堵墙：

- **工具中心点（TCP）不是物理表面点**：TCP 是夹爪两指之间悬空定义的虚拟坐标系原点，投影到图像上往往落在背景像素里，常规表面点跟踪器根本“抓不住”它。
- **只有 3D 坐标不够控制机器人**：点跟踪器只输出位置、不输出姿态和夹爪开合；靠跟踪一组刚体点再事后拟合 $\mathrm{SE}(3)$ 位姿，不仅需要额外机器人先验，还容易在遮挡下误差累积、频繁失败。
- **跨本体数据增广高度依赖源动作日志**：现有跨本体视觉迁移（如 RoVi-Aug、OXE-AugE）必须先有源机器人的精确位姿日志，无法直接利用纯视频示范。

## 研究动机

**核心思路：以本体无关的末端工具中心点（TCP $\mathrm{SE}(3)$ + 夹爪状态）作为统一动作接口，在同一个 4D 场景表征里把“从视频反推动作（Tracking）”和“看历史预测未来动作（Generation）”合二为一。**

这带来一石三鸟的收益：

- **免后处理直接追虚拟 TCP**：在 4D 几何特征上用稀疏查询直接回归完整 $\mathrm{SE}(3)$ 位姿与夹爪状态，彻底省掉多阶段刚体拟合，且只需 3–10 条示范即可迁到新机械臂。
- **跟踪特征直接喂给策略**：用跟踪到的历史 TCP 轨迹去 4D 场景特征里采样局部交互特征，再结合腕部视角与语言指令做流匹配动作生成，部署时无需深度相机。
- **纯 RGB 视频就能跨本体增广**：从源视频直接追出 TCP 轨迹 → 抠除并修复源机械臂背景 → 用逆运动学（IK）把同一条 TCP 轨迹渲染到任意目标机械臂上，零源动作日志即可造新本体数据。

## 技术方案

**输入**：跟踪模式接收单目 RGB 视频与首帧 2D TCP 初始查询；生成模式接收过去 4 帧第三人称 RGB、当前关节状态、腕部 RGB 与语言指令。

**过程**：用 4RC 初始化的 DINOv2 4D 骨干编码场景几何与时序特征，跟踪器通过稀疏查询交叉注意力直接回归每帧度量 TCP $\mathrm{SE}(3)$ 位姿与夹爪状态；生成器沿历史轨迹采样局部 4D 特征，经 4 步流匹配 DiT 预测未来 32 步 TCP 动作块。

**输出**：度量场景深度/相机射线、每帧 TCP $\mathrm{SE}(3)$ 位姿与夹爪状态，或面向执行的未来 32 步相机系 TCP 轨迹（经 IK 转为关节指令）。

核心设计拆解（[方法：第 3 节](https://arxiv.org/html/2611.23143v1#S3)）：

- **TCP 跟踪器（Stage 1，1.52B）**：基于 4RC 交替帧内/全局注意力构建 4D 表征，同时接 Dual-DPT 预测度量深度与相机射线。对每条机械臂在首帧查询点周围取 $3\times 3$ 局部特征形成稀疏查询，经 2D RoPE 交叉注意力与时间 Token AdaLN 调制，直接回归平移、连续 6D 旋转（投影回 $\mathrm{SO}(3)$）与夹爪开合。
- **轨迹条件生成器（Stage 2，全模型 2.27B）**：把跟踪到的历史 TCP 3D 位置反投影回图像，用共享查询编码器沿轨迹提取局部 4D 交互 Token；DiT 将本体状态、局部 TCP Token 与噪声动作拼接做自注意力，并交叉关注当前 4D 特征、腕部 DINOv2 特征和 T5 文本特征，4 步 Euler 积分输出未来 32 步动作。
- **无状态日志的跨本体增广**：用跟踪器从源 RGB 视频恢复世界系 TCP 轨迹与夹爪状态 → 用 SAM 3（或 URDF 投影）抠掉源机械臂并视频修复背景 → 用 IK 求解目标机械臂关节并合成渲染，直接产出目标本体训练视频与动作标签。

## 实验结果

| 评测维度 | TCP4D 表现 | 核心对比与设置 |
| --- | --- | --- |
| **TCP 跟踪（DROID / 未见 RoboLab）** | ATE **7.60 mm / 16.07 mm**；APD **74.78% / 43.71%**；跟踪成功率 **100%** | APD 达最强点跟踪+拟合基线（MoSE3 / CoTracker3 / 4RC）的 **4 倍以上**，夹爪准确率 95.84% / 81.92% |
| **少样本跨本体跟踪（UR5）** | 3-shot ATE **12.22 mm**；10-shot ATE **8.85 mm**（夹爪 98.48%） | DROID 预训练后仅用 10 条示范微调即大幅超越 MoSE3（44.56 mm） |
| **跨本体数据增广（DP 策略，4 任务）** | ARX-X5 仅增广 30.5% → 联合训练 **72.0%**（**+41.5 pp**）；源本体 Aloha 53.5% → **65.5%** | 仅凭 Aloha 50 条源视频增广到 ARX-X5 / UR5-WSG（UR5 亦从 32.0% → 39.0%） |
| **操作策略（RoboTwin 48 任务 / 真机 2 任务）** | RoboTwin C2C **69.19%**（第 1）；真机放笔/叠碗均值 **78.33%** | C2C 超越 EventVLA（65.71%）、DP3（54.27%）、$\pi_0$（45.21%）；真机无需深度超越 DP3（63.33%）与 ACT（31.67%） |

**关键证据边界**：策略生成器仅在干净示范上训练，RoboTwin 随机化场景 **C2R 骤降至 10.94%**（低于 Xiaomi-Robotics-0 的 17.85% 和 $\pi_0$ 的 16.15%），说明目前优势主要在域内精细控制与跟踪—生成统一接口，泛化仍需大规模多样预训练补齐。[实验：第 4 节](https://arxiv.org/html/2611.23143v1#S4)。

## 总结讨论

TCP4D 的亮点在于找准了一个非常贴合机器人工程的切口：**通用 4D 点跟踪器追的是“表面像素”，而机器人真正需要的是“悬空工具坐标系的 $\mathrm{SE}(3)$ + 夹爪”**。把这一接口做成统一的前馈 4D 跟踪+生成模型，既让互联网/无标注机器人视频能直接变现为跨本体训练数据，又让操作策略免深度地用上了 4D 几何特征。

但须清醒看到其当前阶段定位：跟踪器和跨本体增广的实用价值已经很扎实，而策略生成端因缺少多源大规模预训练，面对背景/光照随机化（C2R 10.94%）还很脆弱；且当前仅覆盖两指平行夹爪与固定底座机械臂，尚未延伸至灵巧手或移动操作。

## 局限、失败案例与开放问题

- **域随机化泛化偏弱**：生成器仅用 RoboTwin 干净示范训练，Clean2Random 成功率从 69.19% 跌至 10.94%，跨外观/布局泛化有待大规模预训练验证。
- **模型体量较大且输入分辨率偏低**：完整模型约 2.27B 参数，Stage 1/2 训练与测试分辨率为 $320\times 180$ 或 $320\times 240$，极细小物体操作精度受限。
- **动作接口限于两指夹爪**：TCP $\mathrm{SE}(3)$ + 标量夹爪开合天然适配二指夹爪，尚不支持多指灵巧手或连续力控接触。
- **跨本体增广受限于可达性与背景修复质量**：目标机械臂必须通过 IK 满足源轨迹可达性，且源臂遮挡严重时 SAM 3 分割与视频修复会引入视觉伪影。
- **真机评测规模有限**：物理真机仅在 CoBoT Magic 单平台上测试了两项任务（各 60 条示范、30 次试验），未覆盖强扰动或长程多阶段操作。
