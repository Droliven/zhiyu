## 当前挑战

通用视觉语言骨干擅长解释图像，却未必能在密集场景里准确选中微小目标、区分相邻实例或定位交互部位。直接用少量机器人动作示范同时补齐感知和控制，容易把数据消耗在重新学习“在哪里操作”。对需要闭环动作的任务，语义正确而坐标不准仍会失败。

## 研究动机

**GroundingPI 将精准、语言条件化的视觉 grounding 作为可迁移的基础能力，先学习点和框等视觉基元，再适配动作。** 作者用统一坐标输出覆盖检测、指代定位、指点、OCR、GUI 与文档布局，并在固定下游动作模块的条件下检验：更好的感知预训练能否降低动作学习的数据负担。

它与本库的具身感知和 VLA 表征直接相关。其核心贡献是感知基础与受控迁移验证，尚不能从定位成绩推导出完整动力学理解或通用机器人控制能力。

## 技术方案

**输入**：图像与语言查询；下游机器人策略还接收本体状态，驾驶适配接收前相机图像与历史自车状态。

**过程**：MoonViT-V2 视觉编码器通过可学习投影连接 Qwen3-4B 解码器，语义标签、协议标记及 1,000 个量化坐标 token 共用输出词表。基础多模态训练后，SFT 学习结构化坐标与输出格式，GRPO 用目标覆盖、定位严格度、重复/过大框惩罚及 OCR 文本—几何一致性奖励优化。数据引擎融合多教师字段、按任务校验并迭代标注。用于机器人时，将各层骨干特征注入固定 flow-matching Action DiT，训练连续动作块。

**输出**：基础模型自回归产生点、框及相关语义文本，查询不存在时返回 None；完成下游适配后，可分别输出机器人连续动作或三秒驾驶轨迹。发布的 grounding checkpoint 本身不等于可直接部署的动作策略。

受控骨干比较在每个 benchmark 内固定 Action DiT、动作数据、动作表征、优化预算与推理流程，仅更换预训练感知基础；但不同骨干的预训练数据量、结构与目标仍不相同，不能把差异全部归因于单一 grounding 训练因素。[方法：v2 第 3–4 节](https://arxiv.org/html/2609.39601v2#S3)。

## 实验结果

| 设置 | 作者报告结果 | 可支持的结论与口径 |
| --- | --- | --- |
| 综合感知 | 34 基准、11 类能力、44 个对比模型，聚合得分 73.68；GPT-6 Astra 为 71.54 | 表明所选感知套件总体较强，不是每个任务都最优；不能将异质指标均值视为机器人成功率 |
| RoboTwin 2.0 Full | 成功率 66.20% | Full 同时使用 Clean 与 Randomized 数据训练/评估，不能与只用 Clean 示范的结果直接排名 |
| RoboTwin Clean2Random | 17.60%，Rex-Omni 为 14.10% | 相同动作学习设置下支持场景随机化迁移收益，绝对成功率仍低 |
| RoboCasa-GR1 Full | 37.75%，RynnBrain 为 39.00% | GroundingPI 在该 ID 设置并非最高；三种 OOD 套件均领先所列骨干 |
| 动作数据效率 | 50% 示范达到 28.75%，超过对比骨干用 75% 示范的最高 27.75% | RoboCasa-GR1 ID；固定其余动作学习设置，支持预训练感知改善示范效率 |
| nuScenes 轨迹预测 | 平均开放环 L2 0.296 m，Qwen3-VL 为 0.301 m | 六个 waypoint 覆盖三秒；只验证记录轨迹上的开放环误差，没有闭环驾驶验证 |

论文中的“四个 OOD”是 RoboTwin Clean2Random 与 RoboCasa 的 Appearance、Combinations/Container、Object Types 三套合计，不能写成 RoboTwin 自己有四种 OOD。感知数据规模增加时，下游表现总体改善；分组消融显示密集定位监督有迁移价值。OCR 可促进其他感知能力的解释仍属于机制假说，分组混合结果并非严格独立效应量。[主实验与消融：v2 第 5 节、附录第 8–10 节](https://arxiv.org/html/2609.39601v2#S5)。

## 总结讨论

论文最有分量的证据是固定动作头和训练流程后，不同感知基础仍带来明显的数据效率与 OOD 差异，说明策略底座应评估细粒度 grounding，而不只看通用视觉问答能力。点/框协议也使感知输出更适合工具调用和自动标注。

与 SLA 的区别是：GroundingPI 先训练感知专用骨干，再连接动作学习器；SLA 用冻结三维教师对齐已有 VLA 的中间视觉特征。两者都关注控制可利用的视觉表示，但论文没有验证将它们叠加后的收益。GroundingPI 不负责长期未来仿真，也没有展示在线技能学习或递归自我改进。

## 代码与数据

[官方仓库](https://github.com/groundingpi/GroundingPI) 已提供服务、评测、SFT 训练与下游骨干比较工作流，[模型页](https://huggingface.co/GroundingPI/GroundingPI) 发布 grounding 权重。项目原创代码标注 Apache-2.0，Kimi-derived 组件仍保留 Kimi K3 上游条款，不能将整个模型包概括为无附加上游条件的 Apache-2.0。

仓库说明下游比较依赖单独环境和策略 checkpoint，未提供发布版 GroundingPI 权重可直接使用的动作策略适配器；完整预训练标注语料与全部训练阶段的重建条件也未核验为公开。开放 grounding 模型不等于全部机器人控制实验可以直接复现。

## 局限、失败案例与开放问题

- 四个 OOD 设置分属两套操控基准；总体/相对提升不能扩大为每项感知、每个本体或所有环境领先。
- 未隔离骨干预训练数据、模型结构与目标的全部混杂；受控下游比较不等于统一预训练预算的因果消融。
- RoboTwin Clean2Random 绝对成功率仍低，RoboCasa ID 也存在更强骨干；精确定位不是控制成功的充分条件。
- nuScenes 仅开放环轨迹误差，没有真实闭环驾驶或真实机器人策略迁移的充分证据。
- 自动标注可能保留教师错误；OCR 的跨能力促进机制、训练语料开放范围和下游直接部署接口仍需进一步验证。
