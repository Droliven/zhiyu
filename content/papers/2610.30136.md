## 当前挑战

世界动作模型可以联合预测视频和动作，却缺少明确的技能调用、参数化与步骤组织；代码规划 Agent 能重用工具和技能，但往往没有与低层控制共同学习的动态预测。本文针对两者之间的接口：如何让程序结构在生成未来视频和动作时持续提供指导，并在适合时直接调用已有控制技能。

## 研究动机

**AW-0 将程序作为世界动作模型内部可学习的计划表示：代码、未来视频与动作一起生成，让技能结构进入动态预测和控制。** 相比仅在 WAM 外层增加 Agent，它在每层联合注意力中连接三个专家；相比只预测自然语言子目标，代码可表达参数、顺序与可重用函数。另设混合执行模式检验生成程序能否作为执行接口，而默认策略只将代码作为条件。

与本库 WAM、技能结构和 Agent 工具调用直接相关。其结果支持结构化程序监督改善所测任务的控制表现，尚未证明技能库能在部署时自行扩展或通过持续交互改进学习算法。

## 技术方案

**输入**：当前三个 RGB 视角、任务指令、机器人本体状态；论文设计还包含压缩后的历史程序片段，但公开默认配置是否启用须另核对（见下文）。真实机器人及人手数据映射到 64 维状态/动作空间；RoboTwin 使用 14 维关节空间。YAM 是 I2RT 的 **Yet Another Manipulator** 机械臂；本文 YAM station 使用两条 6-DoF 手臂与平行夹爪。[厂商定义](https://doc.i2rt.com/products/yam)。

**过程**：Mixture-of-Transformers 连接代码、视频、动作专家，专家内双向注意力，跨专家按代码→视频→动作建立分块因果关系。SDAR-1.7B 初始化的代码专家读取冻结 Qwen3-VL 视觉塔特征，通过 LLaDA 风格离散掩码扩散生成程序；Cosmos-Predict2.5-2B 视频专家与动作 DiT 采用连续 flow matching。代码在去噪全过程指导视频和动作，动作还读取视频表示；视频噪声重采样与重要性权重平衡视频学习和控制指导。

**输出**：当前子任务的代码片段、未来视频和连续动作块。默认模式由动作块驱动机器人；混合模式只有在阶段、依赖、语法、API 白名单等检查通过时尝试执行代码，否则采用动作块。

程序标注先从每任务一个 episode 发现可复用模式，再冻结包含 50 项的技能库（23 项 YAM、27 项人类技能），重标种子并缓存子任务到代码的映射，随后按接触/运动证据复用或重新标注。预训练语料为 248,642 episodes、606 任务、2,913.22 小时（YAM 1,919.30 小时、人类第一视角 993.91 小时）；下游仍需对任务示范标注和联合微调。

混合执行调用独立感知与控制原语：仿真中包含 Molmo grounding、SAM 3、Contact-GraspNet 与 RoboTwin 原生运动规划器。评估时不读取特权状态；收集混合模式示范时使用特权物体状态和标注抓取。执行尝试报错后在下一轮重新观测与规划，并非自动修复本轮程序。[方法、附录 A/B/I/J](https://arxiv.org/html/2610.30136v1#S2)。

### 从演示到程序监督

附录 K 描述的是把**已经发生的演示翻译成程序标签**。这里的标注 VLM 与协调 Agent 是离线数据工具，不是部署时的 code expert；后者学习预测这些标签。

1. **取得语义子任务及时间范围。** 例如把一次演示划为“抓杯子”“把杯子放进托盘”。官方实现优先读取已有的人工 `annotation.sub_task`；也支持以夹爪开闭或触觉接触变化确定边界，再让 VLM 命名。预训练若没有子任务来源，还可退化为整 episode 一段。不能把这些边界一概说成模型自动发现。
2. **给标注器证据。** 每次输入总体指令、当前子任务文字、带时间戳的画面、前面子任务已写的程序；YAM 另有传感器导出的夹爪事件列表。
3. **按限定词汇写当前块。** 标注器只能调用给定 primitive API 和已批准技能；匹配时优先使用较高层技能，只输出当前子任务的新代码，并以完整语句结束。此处 API 主要是声明和语义契约，并不执行机器人。
4. **检查标签。** 静态检查语法、函数、参数绑定及允许的字面量，失败则反馈重写；再核对代码隐含的接触/开闭事件与演示是否一致。YAM 的事件列表是硬约束；第一视角人手没有向标注器提供权威接触列表，需从画面及文字推断。事件匹配不等于轨迹、几何参数和接触力均正确。
5. **建立并冻结技能库。** 种子阶段每任务取一个 episode，协调 Agent 审阅反复出现的模式，将跨任务复用、可参数化的动作组合纳入库。协调器负责审阅与技能准入，程序由标注器生成。库冻结后，用最终词汇重标种子并缓存映射。
6. **扩展到全语料。** 证据匹配时复用缓存，否则重新标注并加入缓存。YAM 核对接触序列，允许左右镜像并重新推导运动参数；人手按手部运动轮廓筛选，循环模板不直接复用。新增缓存条目不等于部署中学习了新技能。

因此，“自动代码标注”不意味着无人工语义来源，也不意味着程序已在环境里执行通过。官方文档另支持针对窄任务手写标准程序的路线；RoboTwin 的 CaP 采集则先执行程序并记录动作来源行，具有执行来源信息，应与真实/人手演示的事后语义标注区分。[附录 K](https://arxiv.org/html/2610.30136v1#A11)、[官方标注文档](https://github.com/ZhuoyangLiu2005/agentic-wam/blob/275818e5787d59012eba4c43504342f1201ad25b/docs/CODE_ANNOTATION.md)。

### 训练窗口与程序片段的时间关系

**语义子任务的 code slice 与固定长度的动作窗口是两种粒度。** 标注先给子任务一整块程序，再把该子任务内的每帧映射到这整个块；不是按帧数比例把 Python token 切碎。源文件中 `frame_src_block[f] = [a,b]` 表示帧 `f` 使用程序第 `a` 至 `b` 行，训练缓存再把代码字符串去重，按当前采样帧查标签。

下面是为解释机制构造的例子，不是论文实验记录：

| 演示帧范围 | 语义子任务 | 所挂的完整代码块 |
| --- | --- | --- |
| 0–79 | 右手抓起杯子 | `robot.pick('cup', 'right')` |
| 80–159 | 放入托盘 | `robot.place('cup', 'tray', 'right')` |
| 160–239 | 左手拿起另一物体 | 另一个完整子任务块 |

从第 100 帧、第 110 帧分别抽取训练窗口时，两个样本的动作/未来视频目标不同，code target 却可以相同，都是完整的“放入托盘”块。公开配置的动作 horizon 是 32 步，视频取偏移 `0,4,…,32` 的九帧；**代码块可以概括更长的子任务，并不与这 32 步逐行同步**。已核对的 flat-cache 路径按窗口起点取 code；起点接近子任务末尾时，不能据此宣称窗口跨到的后续代码也会拼进目标。

论文所谓历史 code 是前面已标注/生成的程序片段，active slice 是当前要预测的子任务程序；“未来”指当前观测之后要做或继续做的操作，不是整份 Python 尚未写出的 token 后缀。标准掩码监督只遮盖当前程序目标并预测被遮住的 token，观测和普通条件保持可读；预训练另有 15% batch 同时遮盖 instruction 与 program 输入的 dropout。去噪前后与机器人时间先后是两条轴：公式的 `C_0` 表示干净代码，不是 episode 第零段。[整块映射源码](https://github.com/ZhuoyangLiu2005/agentic-wam/blob/275818e5787d59012eba4c43504342f1201ad25b/codegen/pretrain/pipeline/codegen/pipeline/episode.py#L344)、[窗口起点查标签](https://github.com/ZhuoyangLiu2005/agentic-wam/blob/275818e5787d59012eba4c43504342f1201ad25b/src/agenticwam/datasets/lerobot/robot_video_dataset.py#L355)、[附录 A](https://arxiv.org/html/2610.30136v1#A1)。

### 闭环推理怎样接续程序计划

每次 replanning 都重新读当前画面、任务及状态，重建 prompt，并接上全新的 `[MASK]` canvas；在联合去噪中产生本轮 code、video、action。默认执行本轮动作块，取得新的真实观测后再次预测。**接续的是任务语义与状态，不是从上轮代码最后一个 token 接着写。** 同一子任务尚未完成时，下一轮仍可能输出同类甚至相同代码；默认模式不会因此重新从头执行那个完整技能。

按论文 §2.3 的 memory 设计，已生成的片段追加到 episode 历史，压缩进可学习 memory slots，供下一轮读回；训练主要使用先前标注片段，并以概率用模型预测替换。必须注意：历史记录的是“生成过的计划”，不保证计划对应动作已经成功完成；真实进度还需当前观测提供证据。Hybrid 在通过检查后才切到代码执行，并另有共享执行命名空间及进度/依赖检查，不宜把它当成默认模式的代码续写机制。[§2.3](https://arxiv.org/html/2610.30136v1#S2.SS3)、[新 canvas 与历史追加的推理实现](https://github.com/ZhuoyangLiu2005/agentic-wam/blob/275818e5787d59012eba4c43504342f1201ad25b/src/agenticwam/models/cosmos_mot/agenticwam_model.py)。

| 设置 | 作者报告结果 | 证据边界 |
| --- | --- | --- |
| RoboTwin 2.0 默认模式 | Clean 80.8%、Random 20.6%、两者均值 50.7%；π₀.₅ 为 54.9/27.7/41.3，WLA 为 64.8/3.6/34.2 | 50 任务，每任务 50 条 clean 示范、每设置 50 rollouts；优势主要来自 clean，默认模式在 Random 低于 π₀.₅ |
| RoboTwin 混合模式 | Clean 63.1%、Random 29.2%、均值 46.2% | 同时改变为 CaP 采集示范与混合执行，不能将相对默认模式的差值单独归因于代码执行 |
| 两平台八项真机任务 | 平均 rubric score 71.1%，最强对比 DreamZero 为 46.0% | 每任务 100 示范，3 训练种子×16 rollouts；是可获得部分进度的评分，不是完整 episode 成功率 |
| 真机折叠堆毛巾 | 混合执行 rubric score 90.6%，默认动作执行 84.4% | 同一后训练模型与任务条件下比较，证据比仿真混合对照更直接；仅 YAM 一项任务 |
| 代码视觉输入消融 | ViT 平均 rubric score 71.1%，复用 VAE 特征为 55.6% | 八项任务同协议，支持专门语义视觉特征的价值 |
| 联合去噪与自回归代码 | 联合模式平均 71.1%，AR 54.5%；端到端延迟 0.23 s 对 0.55 s | 单 RTX 5090；延迟包含视觉编码、去噪、视频解码与动作后处理，不能视为机器人控制频率 |

相同预训练数据、预算与优化条件下，代码→视频→动作优于无代码及视频→代码→动作配置；删除技能调用、解释性注释也降低所测任务表现。这些消融支持程序内容及其信息流的作用，不能据此认定所有生成程序具有正确物理语义。[正文第 3 节、表 1–4 与附录 J](https://arxiv.org/html/2610.30136v1#S3)。

## 总结讨论

贡献在于把代码从外层任务规划器推进到 WAM 内部，与视频和动作共同优化；自动标注与冻结技能库为这种接口提供规模化监督。默认模式检验程序计划对学习式控制的指导，混合模式进一步检验显式技能与动作专家的互补。

混合执行的可靠性仍受感知、抓取和规划原语限制；通过有效性检查不代表比动作专家更优，因而混合模式在 clean 条件明显退化。与 PrimeSim 的接口区别是：PrimeSim 输入外部动作、模拟视觉后果，AW-0 自身联合产生计划和策略动作。AW-0 当前不从部署交互在线学习，其持续技能扩展和自我改进属于未来方向。

### 阅读讨论（2026-11-11）

**默认 code branch 可理解为学习得到的结构化语义计划条件。** 它对“操作谁、用哪只手、调用什么技能、按什么顺序和次数”作显式表达，通过隐藏表示和逐层注意力影响视频及动作；默认控制输出仍由 action expert 产生。把它类比为更细的任务提示有助理解，但“只是普通文本提示，作用有限”比证据走得更远：论文对自然语言 subgoal、移除技能调用和改变信息流的消融支持结构化代码在所测任务上的价值，未证明这种表示在所有任务中必要或最优。

用户指出的**生成代码缺少稳定直接执行保证**是成立的边界。附录 F 展示选对技能但参数错误，以及正确技能调用伴随注释格式错误的情形；附录 L 也明确说语法有效不等于执行正确。但这不能归因于采用离散掩码生成：`[MASK]` 遮的是代码 token，与图像 segmentation mask 无关，也不能单凭生成范式判断几何能力。

**语义视觉 grounding、显式几何定位、实际执行可靠性须分别验证。** code expert 有当前多视角 ViT 条件；人手标注明确采用无坐标的语义运动，YAM 代码则可通过感知 API 取得 pose，hybrid 更会调用外部定位、分割、抓取和规划系统。因此不能说整套系统完全没有 2D/3D grounding；更准确的阅读判断是：默认 code stream 没有被证明能独立维护精细、可靠的几何状态与接触约束，给出对象名或技能名也不保证动作参数和物理执行正确。[§3.3、附录 F/K/L](https://arxiv.org/html/2610.30136v1)、[作者项目页](https://agentic-wam.github.io/)。

### Agentic 命名的含义与边界

“代码生成只是离线单次”的说法需要区分标签与模型输出：离线标注 Agent 生成训练程序并整理技能库；部署时的 code expert 则在每个 replanning point 根据当前观测重新生成片段，与视频和动作共同去噪。它不需要持续调用离线标注所用的外部 Gemini/Claude，也不是 episode 开始时只生成一次完整程序。[§2.3](https://arxiv.org/html/2610.30136v1#S2.SS3)。

本文的 agentic 有三层来源：离线阶段有分工、审阅与技能整理的 Agent 工作流；默认策略把对象参数、技能调用和程序结构引入 WAM 的计划表示；hybrid 进一步在环境中实际调用感知/控制 API，并在下一轮观测后重新决策。默认策略具有闭环动作控制，但没有逐段执行生成程序的工具调用闭环。仅凭生成代码这一点，还不足以证明自主程序调试、执行反馈驱动的技能改进或开放式长期任务管理。

因此，阅读判断是：默认 AW-0 的 agentic 主要体现为程序化计划及可复用技能接口，hybrid 才进一步检验程序作为执行接口。它确实超出了纯离线标签，但也不能据名称扩大成持续运行的通用 coding agent。附录 L 将技能扩展、进一步的计划修订与持续交互自主学习列为未来方向，并明确当前系统不从交互在线学习。持续学习与 agentic 是不同维度；固定权重系统也可以循环决策、调用工具，缺少在线学习本身不能否定全部 agentic 行为。[附录 I、L](https://arxiv.org/html/2610.30136v1#A12)、[作者项目页](https://agentic-wam.github.io/)。

### 论文设计与公开配置的差别

当前公开实现提供 `LearnedCodeMemory`，以及 `code_slices` 路径中的历史/当前片段分离，但基础模型配置设 `code_memory: false`，公开预训练配置使用 flat frame cache 且 `code_slices: false`。这说明记忆路径的代码存在，**不能据此认定所有公开训练配方或发布 checkpoint 默认都启用论文所述 memory**；本次未逐个检查 checkpoint 的实际配置及权重。复现历史接续能力时，应核对模型开关、数据是否真的提供历史和部署 reset/追加逻辑，而非只引用论文框架图。[模型基础配置](https://github.com/ZhuoyangLiu2005/agentic-wam/blob/275818e5787d59012eba4c43504342f1201ad25b/configs/model/agenticwam_cosmos.yaml#L62)、[预训练数据配置](https://github.com/ZhuoyangLiu2005/agentic-wam/blob/275818e5787d59012eba4c43504342f1201ad25b/configs/real_pre_train/data/pretrain_magic_soup.yaml#L43)、[记忆模块](https://github.com/ZhuoyangLiu2005/agentic-wam/blob/275818e5787d59012eba4c43504342f1201ad25b/src/agenticwam/models/experts/code_memory.py)。

## 代码与数据

## 局限、失败案例与开放问题

- 程序监督来自自动标注与有限技能库；函数参数错误、接触失败和物体属性误判仍会传递到控制，语法正确不保证执行正确。
- 默认模式从 Clean 80.8% 降到 Random 20.6%，显示明显的视觉分布偏移；混合配置也未同时兼顾 clean 与随机环境。
- 仿真混合结果同时改变示范采集与执行工具，缺少只切换执行模式的严格对照；真机混合证据仅覆盖 YAM 折叠任务。
- 真机主指标是八任务平均进度评分；71.1% 不能改写为全任务成功率，少数任务不能代表广泛跨任务泛化。
- 当前部署没有在线学习、自主技能库扩展或经受控验证的递归自我改进；完整预训练数据和部分初始化材料未随发布提供。
