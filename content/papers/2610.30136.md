## 当前挑战

世界动作模型可以联合预测视频和动作，却缺少明确的技能调用、参数化与步骤组织；代码规划 Agent 能重用工具和技能，但往往没有与低层控制共同学习的动态预测。本文针对两者之间的接口：如何让程序结构在生成未来视频和动作时持续提供指导，并在适合时直接调用已有控制技能。

## 研究动机

**AW-0 将程序作为世界动作模型内部可学习的计划表示：代码、未来视频与动作一起生成，让技能结构进入动态预测和控制。** 相比仅在 WAM 外层增加 Agent，它在每层联合注意力中连接三个专家；相比只预测自然语言子目标，代码可表达参数、顺序与可重用函数。另设混合执行模式检验生成程序能否作为执行接口，而默认策略只将代码作为条件。

与本库 WAM、技能结构和 Agent 工具调用直接相关。其结果支持结构化程序监督改善所测任务的控制表现，尚未证明技能库能在部署时自行扩展或通过持续交互改进学习算法。

## 技术方案

**输入**：当前三个 RGB 视角、任务指令、机器人本体状态，以及压缩后的历史程序片段。真实机器人及人手数据映射到 64 维状态/动作空间；RoboTwin 使用 14 维关节空间。

**过程**：Mixture-of-Transformers 连接代码、视频、动作专家，专家内双向注意力，跨专家按代码→视频→动作建立分块因果关系。SDAR-1.7B 初始化的代码专家读取冻结 Qwen3-VL 视觉塔特征，通过 LLaDA 风格离散掩码扩散生成程序；Cosmos-Predict2.5-2B 视频专家与动作 DiT 采用连续 flow matching。代码在去噪全过程指导视频和动作，动作还读取视频表示；视频噪声重采样与重要性权重平衡视频学习和控制指导。

**输出**：当前子任务的代码片段、未来视频和连续动作块。默认模式由动作块驱动机器人；混合模式只有在阶段、依赖、语法、API 白名单等检查通过时尝试执行代码，否则采用动作块。

程序标注先从每任务一个 episode 发现可复用模式，再冻结包含 50 项的技能库（23 项 YAM、27 项人类技能），重标种子并缓存子任务到代码的映射，随后按接触/运动证据复用或重新标注。预训练语料为 248,642 episodes、606 任务、2,913.22 小时（YAM 1,919.30 小时、人类第一视角 993.91 小时）；下游仍需对任务示范标注和联合微调。

混合执行调用独立感知与控制原语：仿真中包含 Molmo grounding、SAM 3、Contact-GraspNet 与 RoboTwin 原生运动规划器。评估时不读取特权状态；收集混合模式示范时使用特权物体状态和标注抓取。执行尝试报错后在下一轮重新观测与规划，并非自动修复本轮程序。[方法、附录 A/B/I/J](https://arxiv.org/html/2610.30136v1#S2)。

## 实验结果

| 设置 | 作者报告结果 | 证据边界 |
| --- | --- | --- |
| RoboTwin 2.0 默认模式 | Clean 80.8%、Random 20.6%、两者均值 50.7%；π₀.₅ 为 54.9/27.7/41.3，WLA 为 64.8/3.6/34.2 | 50 任务，每任务 50 条 clean 示范、每设置 50 rollouts；优势主要来自 clean，默认模式在 Random 低于 π₀.₅ |
| RoboTwin 混合模式 | Clean 63.1%、Random 29.2%、均值 46.2% | 同时改变为 CaP 采集示范与混合执行，不能将相对默认模式的差值单独归因于代码执行 |
| 两平台八项真机任务 | 平均 rubric score 71.1%，最强对比 DreamZero 为 46.0% | 每任务 100 示范，3 训练种子×16 rollouts；是可获得部分进度的评分，不是完整 episode 成功率 |
| 真机折叠堆毛巾 | 混合执行 rubric score 90.6%，默认动作执行 84.4% | 同一后训练模型与任务条件下比较，证据比仿真混合对照更直接；仅 YAM 一项任务 |
| 代码视觉输入消融 | ViT 平均 rubric score 71.1%，复用 VAE 特征为 55.6% | 八项任务同协议，支持专门语义视觉特征的价值 |
| 联合去噪与自回归代码 | 联合模式平均 71.1%，AR 54.5%；端到端延迟 0.23 s 对 0.55 s | 单 RTX 5090；延迟包含视觉编码、去噪、视频解码与动作后处理，不能视为机器人控制频率 |

相同预训练数据、预算与优化条件下，代码→视频→动作优于无代码及视频→代码→动作配置；删除技能调用、解释性注释也降低所测任务表现。这些消融支持程序内容及其信息流的作用，不能据此认定所有生成程序具有正确物理语义。[正文第 3 节、表 1–4 与附录 J](https://arxiv.org/html/2610.30136v1#S3)。

## 总结讨论

贡献在于把代码从外层任务规划器推进到 WAM 内部，与视频和动作共同优化；自动标注与冻结技能库为这种接口提供规模化监督。默认模式检验程序计划对学习式控制的指导，混合模式进一步检验显式技能与动作专家的互补。

混合执行的可靠性仍受感知、抓取和规划原语限制；通过有效性检查不代表比动作专家更优，因而混合模式在 clean 条件明显退化。与 PrimeSim 的接口区别是：PrimeSim 输入外部动作、模拟视觉后果，AW-0 自身联合产生计划和策略动作。AW-0 当前不从部署交互在线学习，其持续技能扩展和自我改进属于未来方向。

## 局限、失败案例与开放问题

- 程序监督来自自动标注与有限技能库；函数参数错误、接触失败和物体属性误判仍会传递到控制，语法正确不保证执行正确。
- 默认模式从 Clean 80.8% 降到 Random 20.6%，显示明显的视觉分布偏移；混合配置也未同时兼顾 clean 与随机环境。
- 仿真混合结果同时改变示范采集与执行工具，缺少只切换执行模式的严格对照；真机混合证据仅覆盖 YAM 折叠任务。
- 真机主指标是八任务平均进度评分；71.1% 不能改写为全任务成功率，少数任务不能代表广泛跨任务泛化。
- 当前部署没有在线学习、自主技能库扩展或经受控验证的递归自我改进；完整预训练数据和部分初始化材料未随发布提供。
