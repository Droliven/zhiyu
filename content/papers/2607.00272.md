## 当前挑战

任务失败并不说明应修改感知、抓取还是规划。单回合重试即使找到修复，新任务也可能重新踩坑；完整历史又难以检索。缺的是可归因的执行证据，以及经过验证、能供后来程序使用的修复知识。

## 研究动机

**把失败后的局部修复沉淀为有适用条件的技能，而非只保存成功脚本。** ASPIRE 在冻结语言模型之外积累程序与经验，直接对应本库关注的跨回合自我改进；模型权重不更新。

## 技术方案

**输入**：任务、预定义机器人 API、当前程序、逐原语执行记录及共享技能库；记录包含调用参数、状态、前后图像和规划结果。

**过程**：Actor 诊断、改程序并重执行；进化搜索提出多个候选。技能保存失败特征、适用条件、修复策略和可选代码草图，由新 verifier 独立复现后入库。Coordinator 编排任务，并允许早期低分任务利用最终技能库再调试。

**输出**：可执行程序与可检索的修复知识。它改变后续求解的起点，未证明搜索或验证算法自身获得递归改进。[方法 §2](https://arxiv.org/html/2607.00272v2#S2)。

## 实验结果

调试与评估 seeds 分离；LIBERO-Pro/Robosuite 每任务保留一个程序，不能与逐 seed 重写、重试的基线视为等预算比较。

| 证据 | 作者报告与口径 |
| --- | --- |
| 未见长任务迁移 | Opus 4.6，LIBERO-90 积累库→LIBERO-Pro Long；两种扰动各十任务、每任务50 seeds，每任务一个程序，测试无调试、重试或库更新。附录表8空库为4.7%，90任务库为30.5% |
| 真机跨本体适配 | 拾罐由13/20→19/20；达到首个成功程序的总 token 由61.94M→6.58M。仍在真机调试，并非仿真程序直接部署 |

迁移表8与表9逐任务均值略有出入，上表保留表8口径。魔方三回合仅提供同 session 经验积累的案例，且需人工打乱和重置；搜索成本不能只用部署调用量概括。[§3.3–3.7、附录C](https://arxiv.org/html/2607.00272v2#S3)。

## 总结讨论

最有价值的增量是“执行证据→验证修复→后续复用”。它比当前回合恢复多了持久变化，但库增长、模型变强或反复运行固定搜索，都不足以证明改进机制自身越来越有效。

## 局限、失败案例与开放问题

- 技能仅在入库时验证，规模增长后可能过期、冲突或误导新任务。
- 受冻结模型和预定义 API 限制，搜索消耗大量调用与 rollout。
- 真机任务与样本有限，尚无自主重置和长期无人值守证据。
